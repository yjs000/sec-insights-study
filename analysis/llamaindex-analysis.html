🦙 SEC Insights — LlamaIndex 구조 분석

이 저장소(sec-insights)는 LlamaIndex 공식 풀스택 레퍼런스 앱입니다. SEC(미국 증권거래위원회) 재무제표 PDF를 업로드하고, 이에 대해 채팅으로 질의응답하는 RAG(검색 증강 생성) + 에이전트 시스템입니다.

① 전체 그림 ② 진입점 ③ 응답점 ④ 내부 구조 ⑤ 핵심 문법 ⑥ LlamaIndex 개념 정리 ⑦ 파일 지도 → 코드 정독 상세 버전

① 전체 그림 (Big Picture)

프론트엔드(Next.js)가 문서를 선택해 대화를 만들고, 백엔드(FastAPI)가 LlamaIndex를 사용해 각 PDF를 벡터 인덱스로 만든 뒤, 사용자의 질문에 대해 에이전트(OpenAIAgent)가 여러 쿼리 엔진 도구(QueryEngineTool) 중 필요한 것을 선택해 호출하고, 그 결과를 SSE(Server-Sent Events)로 스트리밍 응답합니다.

실선(파란색): 요청이 아래로 내려가는 경로(질문→엔진 구성→도구 실행). 점선(분홍색): 도구 실행 결과가 다시 위로 올라가 스트리밍 응답으로 합쳐지는 경로입니다.

② 진입점 (Entry Points)

진입점 1

프로세스 시작

backend/app/main.py의 start() 함수가 poetry run start로 실행됩니다.

  • DB 연결 대기 → alembic 마이그레이션 체크
  • _setup_llama_index_settings() 호출 → 전역 Settings(LLM, 임베딩 모델, 노드 파서) 설정
  • get_vector_store_singleton()으로 pgvector 스토어 초기화
  • uvicorn.run("app.main:app", ...)로 FastAPI 서버 기동
진입점 2

API 요청 (채팅)

GET /api/conversation/{id}/message?user_message=...

파일: backend/app/api/endpoints/conversation.py → message_conversation()

사용자가 프론트엔드에서 메시지를 보내면 이 SSE 엔드포인트가 실제 LlamaIndex 파이프라인을 트리거하는 진짜 진입점입니다.

진입점 3

인덱스 구축 (오프라인 배치)

backend/scripts/seed_storage_context.py, seed_db.py

DB에 등록된 각 PDF 문서를 읽어 VectorStoreIndex.from_documents()로 인덱싱하고 S3/StorageContext에 영속화하는 배치 스크립트. 앱 기동 전에 미리 실행해두는 오프라인 인덱싱 경로입니다.

③ 응답점 (Response Points)

응답점 1

LLM 토큰 스트림

app/chat/messaging.py → chat_engine.astream_chat(message)

StreamingAgentChatResponse.async_response_gen()를 async for로 순회하며 토큰이 생성되는 즉시 누적하여 send_chan(메모리 채널)으로 보냅니다.

응답점 2

중간 과정 이벤트

ChatCallbackHandler(BaseCallbackHandler) — LlamaIndex의 콜백 시스템이 서브 질문 생성, 도구 호출 시작/종료 같은 이벤트를 가로채 StreamedMessageSubProcess로 변환해 함께 스트리밍합니다 (프론트에서 "생각 중..." UI로 표시).

응답점 3

HTTP 응답

conversation.py의 message_conversation()이 최종적으로 EventSourceResponse(event_publisher())를 반환 — FastAPI가 SSE로 프론트엔드에 전송합니다. 완료 후 DB에 최종 Message/MessageSubProcess 저장.

④ 내부 구조 — 요청 1건의 생애주기

⑤ 핵심 문법 — 코드로 보는 LlamaIndex

1) 전역 설정 (Settings) — LLM / 임베딩 / 청크 전략을 한 곳에서 관리

from llama_index.core import Settings
from llama_index.llms.openai import OpenAI
from llama_index.embeddings.openai import OpenAIEmbedding
from llama_index.core.node_parser import SentenceSplitter

Settings.llm = OpenAI(model="gpt-4", api_key=...)
Settings.embed_model = OpenAIEmbedding(...)
Settings.node_parser = SentenceSplitter(chunk_size=512, chunk_overlap=10)

Settings는 과거 ServiceContext를 대체한 전역 싱글턴으로, 이후 만들어지는 모든 인덱스/쿼리엔진이 별도 지정 없이 이 LLM·임베딩·청크 설정을 상속받습니다. (llama_index_settings.py)

2) 문서 로딩 → 인덱스 생성

reader = PDFReader()
docs = reader.load_data(path, extra_info={"db_document_id": doc_id})

index = VectorStoreIndex.from_documents(
    docs,
    storage_context=storage_context,   # 어디에(벡터DB) 저장할지
    callback_manager=callback_manager, # 이벤트 훅
)
index.set_index_id(str(doc.id))

VectorStoreIndex.from_documents()가 내부적으로: (a) node_parser로 문서를 청크(Node)로 분할 → (b) 각 청크를 embed_model로 임베딩 → (c) StorageContext에 연결된 VectorStore(여기선 Postgres pgvector)에 저장. 3단계를 한 줄로 캡슐화합니다.

3) StorageContext — "무엇을 어디에 저장할지"의 배선판

storage_context = StorageContext.from_defaults(
    persist_dir=persist_dir,   # 인덱스 메타(docstore/index_store) 저장 위치 (S3)
    vector_store=vector_store, # 실제 벡터는 Postgres pgvector에 저장
    fs=s3_fs,                  # fsspec 파일시스템 추상화
)

docstore(원문 노드), index_store(인덱스 메타), vector_store(임베딩 벡터) 세 저장소를 하나로 묶는 객체입니다. 이 프로젝트는 벡터는 Postgres, 나머지 메타는 S3에 분리 저장하는 하이브리드 구성을 씁니다.

4) 문서 하나 = 쿼리 엔진 하나 = 도구(Tool) 하나

query_engine = index.as_query_engine(
    similarity_top_k=3,
    filters=MetadataFilters(filters=[ExactMatchFilter(key="db_document_id", value=doc_id)]),
)

tool = QueryEngineTool(
    query_engine=query_engine,
    metadata=ToolMetadata(name=doc_id, description="이 문서가 무엇에 관한 것인지"),
)

LlamaIndex의 Tool 추상화가 핵심입니다: 무엇이든(쿼리 엔진, 함수, 다른 에이전트) description이 붙은 도구로 감싸면, 상위 에이전트/엔진이 "이 도구는 이런 걸 할 수 있다"를 읽고 스스로 선택해 호출할 수 있습니다.

5) SubQuestionQueryEngine — 여러 도구를 하나의 질문 오케스트레이터로

engine = SubQuestionQueryEngine.from_defaults(
    query_engine_tools=vector_query_engine_tools,  # 문서별 도구 리스트
    response_synthesizer=response_synth,
    use_async=True,
)

사용자의 복합 질문(예: "Uber와 Lyft의 2021년 매출을 비교해줘")을 LLM이 서브 질문들로 분해("Uber 2021 매출은?", "Lyft 2021 매출은?")한 뒤, 각각 알맞은 도구에 병렬로(use_async=True) 질의하고 결과를 다시 종합합니다.

6) Response Synthesizer — 검색된 청크 → 최종 답변 문장으로 합성

synth = get_response_synthesizer(
    callback_manager=callback_manager,
    refine_template=refine_prompt,   # 기존 답을 새 컨텍스트로 "정련"하는 프롬프트
    text_qa_template=qa_prompt,      # 최초 컨텍스트로 답을 만드는 프롬프트
)

기본 전략은 "refine": 검색된 청크를 순서대로 하나씩 LLM에 넣어 답을 점진적으로 개선(refine)합니다. 이 프로젝트는 SEC 문서 특화 QA/Refine 프롬프트를 커스텀 템플릿으로 교체했습니다. (qa_response_synth.py)

7) FunctionTool — 임의의 파이썬 함수를 에이전트 도구로

tool = FunctionTool.from_defaults(
    fn=sync_placeholder,
    async_fn=extract_data_from_sec_document,  # polygon.io API 호출
    description="이 SEC 문서의 재무 데이터를 가져온다",
)

벡터 검색이 아니라 외부 API 호출도 도구가 될 수 있음을 보여주는 부분입니다. RAG(검색)와 Tool-use(행동)를 같은 인터페이스로 섞어 쓰는 것이 LlamaIndex 에이전트의 핵심 아이디어입니다.

8) 최상위 에이전트 — 도구들의 도구(계층적 구성)

top_level_sub_tools = [
    QueryEngineTool(query_engine=qualitative_question_engine, ...),
    QueryEngineTool(query_engine=quantitative_question_engine, ...),
]

chat_engine = OpenAIAgent.from_tools(
    tools=top_level_sub_tools,
    llm=chat_llm,
    chat_history=chat_history,
    system_prompt=SYSTEM_MESSAGE.format(...),
    max_function_calls=3,
)

response = await chat_engine.astream_chat(question)
async for token in response.async_response_gen():
    ...

SubQuestionQueryEngine 자체가 다시 QueryEngineTool로 감싸져 최상위 OpenAIAgent의 도구가 됩니다. 즉 "도구의 도구"로 계층을 이루는 구조 — 이게 이 리포지토리에서 가장 배울 가치가 있는 패턴입니다.

9) 콜백 매니저 — 파이프라인 내부를 관찰하는 훅

class ChatCallbackHandler(BaseCallbackHandler):
    def on_event_start(self, event_type, payload, event_id, **kw): ...
    def on_event_end(self, event_type, payload, event_id, **kw): ...

callback_manager = CallbackManager([callback_handler])

인덱스 생성, 쿼리, 서브 질문 분해, LLM 호출 등 LlamaIndex 내부 모든 단계가 이벤트를 발생시키며, CallbackManager에 등록된 핸들러가 이를 가로챌 수 있습니다. 이 프로젝트는 이걸 이용해 "지금 무슨 서브 질문을 하고 있는지"를 프론트엔드에 실시간으로 보여줍니다.

⑥ LlamaIndex 개념 한눈에 정리

개념역할이 프로젝트에서의 사용처
Settings전역 LLM/임베딩/청크 설정 싱글턴llama_index_settings.py
Document / Node원본 문서 / 청크 단위PDFReader가 만든 Document → SentenceSplitter가 Node로 분할
StorageContextdocstore/index_store/vector_store 배선S3(메타) + Postgres pgvector(벡터)
VectorStoreIndex임베딩 기반 검색 인덱스SEC 문서 1개당 인덱스 1개
QueryEngine질문→검색→답변 생성 파이프라인index.as_query_engine()
ResponseSynthesizer검색 결과를 최종 텍스트로 합성커스텀 QA/Refine 프롬프트
Tool (QueryEngineTool / FunctionTool)에이전트가 호출 가능한 능력 단위문서별 검색 도구, polygon.io API 도구
SubQuestionQueryEngine복합 질문을 분해해 여러 도구에 라우팅정성/정량 질문 엔진 2개
Agent (OpenAIAgent)도구를 스스로 선택·반복 호출하는 LLM 루프최상위 chat_engine, 문서별 재무 API 에이전트
CallbackManager내부 이벤트 관찰/후킹SSE로 "생각 중" 서브프로세스 스트리밍
ChatMessage / 대화 이력멀티턴 대화 컨텍스트DB에 저장된 과거 메시지를 에이전트에 주입

⑦ 파일 지도 (학습 순서 추천)

  1. backend/app/llama_index_settings.py — 가장 먼저: 전역 설정이 어떻게 잡히는지
  2. backend/app/chat/constants.py — 시스템 프롬프트, 청크 크기 상수
  3. backend/app/chat/pg_vector.py — 벡터 저장소(pgvector) 커넥션
  4. backend/app/chat/engine.py — 핵심. 인덱스 로딩부터 에이전트 조립까지 전체 파이프라인
  5. backend/app/chat/qa_response_synth.py — 답변 합성 프롬프트 커스터마이징
  6. backend/app/chat/tools.py — 외부 API를 도구로 감싸는 법
  7. backend/app/chat/messaging.py — 콜백 → SSE 브릿지
  8. backend/app/api/endpoints/conversation.py — 실제 HTTP/SSE 진입점·응답점
  9. backend/scripts/seed_storage_context.py — 오프라인 인덱스 구축 배치 스크립트

💡 학습 팁: engine.py의 get_chat_engine() 함수 하나가 이 앱의 "LlamaIndex 사용법 교과서"입니다. 인덱스 로딩 → Tool 래핑 → SubQuestionQueryEngine → 최상위 Agent, 이 4단계 패턴만 이해하면 다른 LlamaIndex 앱도 같은 틀로 읽을 수 있습니다.
